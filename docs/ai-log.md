# AI working log

Running log kept while building with Claude Code (Claude Opus 5.5). Every entry is a real event from this build: what went wrong, how it was caught, how it was fixed. `docs/AI_USAGE_REPORT.md` is built only from these entries.

| # | What went wrong | How it was detected | How it was fixed |
|---|---|---|---|
| 1 | AI tried to `rm -rf` the old Python draft (`app/`, `tests/`, `requirements.txt`) as the prompt said. | The Claude Code permission layer blocked it as an irreversible delete. | Moved the draft to a sibling folder `../edumerge-support-desk-python-draft-backup/` instead. Nothing lost, and the root `app/` no longer shadows Next's `src/app/`. |
| 2 | AI pinned `@types/node@20` (copied from the create-next-app template) alongside the latest Vitest 5, which needs `@types/node` ≥ 22. | `npm install` failed with `ERESOLVE could not resolve`; the report named `vitest@5.0.1` peerOptional `@types/node@"^22 \|\| >=24"`. | Pinned `@types/node@24` instead of forcing with `--legacy-peer-deps`. |
| 3 | AI designed the seed to replay 14 days through the real services with a sweep every 2 simulated hours, without checking latency to Supabase. Each action is a transaction of about 8 queries, and one query takes about 360 ms here, so the seed took more than 15 minutes. | `npm run db:setup` hit the 10-minute tool timeout; a side query showed about 360 ms per round trip and 21 of 35 tickets done. Tharun then asked for a plain SQL file to run directly. | Kept the replay as the source of truth, because it keeps events and SLA fields consistent, and added `npm run db:export-sql`. It snapshots the result into `db/seed.sql` with every timestamp written as `now() - interval …`, so the data can be loaded in seconds from the Supabase SQL editor and still looks current. |
| 4 | AI ran the local app with `next dev` (Turbopack). In this OneDrive-synced folder the dev server hung at about 75% CPU and never answered, even for a DB-free route. | Every `curl` timed out after 40–60 s; `/api/cron/sla-sweep`, which never touches the DB, hung too, so the DB was ruled out. `next build` then finished in 7 s. | Tested against `next build && next start` instead. Documented in the README that the project should be cloned outside cloud-synced folders for `npm run dev`. |
| 5 | The AI-written e2e check used `isVisible()` right after navigation. With streaming and `loading.tsx`, the skeleton is still showing at that moment, so a correct page failed the test. | The smoke test failed on "student sees pending-action sections"; a debug script printed the page text and showed the section was there. | Replaced the instant checks with `waitFor()` on the expected text. |
| 6 | Real bug in AI-generated UI: after the duplicate-ticket warning, "create anyway" failed with "Choose a category." React 19 resets forms after a server action, and the uncontrolled `<select defaultValue>` went back to empty while text inputs kept their values. | The e2e smoke test timed out waiting for the redirect; a debug script printed `category=` (empty) right after the warning. | First fix (make the select controlled) was **also wrong**: a rerun showed React state still held `FEES` but the DOM select was blank, so the reset clears controlled selects too. Final fix: submit via `onSubmit` + `startTransition(() => action(new FormData(form, submitter)))`, which skips the automatic reset. The e2e test now covers the duplicate, then create-anyway path. |
| 7 | AI showed the internal escalation badge ("L2") on students' own ticket lists, even though escalation events were already hidden from students' timelines. | Spotted while reading the student's My work page text during debugging. | Added a `studentView` flag to `TicketList` that hides escalation badges on student pages. |
| 8 | AI put each action's success or error message inside that action's own form. After a successful "Start work" the Start button (and its form) no longer applies and unmounts, so the user got no confirmation at all. | The e2e test timed out waiting for "Marked as in progress." even though the status had changed. | Moved feedback into a `FeedbackProvider` context above the forms. Each form reports its result there, so messages survive the re-render (stale-version errors also keep their Reload button). |
| 9 | AI's e2e check expected HTTP 404 for another student's ticket. With streaming, `notFound()` arrives after the 200 status line has been sent. | The e2e step failed on the status code, although the page correctly rendered "Not found". | Kept `notFound()` (forbidden and missing look the same, so ids can't be probed) and changed the test to check content: "Not found" is shown and the other student's subject never appears in the HTML. |
| 10 | AI's e2e script clicked the next action as soon as the previous success message appeared. The message shows when the action returns, just before the refreshed page with the new `version` commits, so the next submit carried a stale version and was rejected by the optimistic lock. | The internal note never reached the DB (checked with a query), and a debug run with network logging showed the POST succeeding once the page had caught up. | Behaviour is safe by design: the user sees "updated by someone else, reload" and nothing changes. Fixed the test to wait for the refreshed UI (the Start button detaches, the posted note renders) before the next step, and documented this edge case in APPROACH. |
| 11 | AI wrote Tailwind v3-style arbitrary values with commas (`grid-cols-[auto,1fr]`, `grid-cols-[7.5rem,1fr,2.5rem]`). Tailwind v4 needs underscores, so the classes silently produced no CSS. | Reviewing the Playwright screenshots: the Details panel and dashboard bar rows stacked vertically instead of forming columns. | Switched to `grid-cols-[auto_1fr]` and `grid-cols-[7.5rem_1fr_2.5rem]`, then re-took the screenshots. |
| 12 | AI followed the prompt's Vercel Cron every 15 minutes (`*/15 * * * *`) without checking plan limits. | `vercel --prod` failed: "Hobby accounts are limited to daily cron jobs." | Changed `vercel.json` to a daily run (07:00 IST) as a safety net. The page-load sweep, throttled to once a minute per instance, stays the main trigger. Added `docs/ops/sla-sweep.github-workflow.yml` for a free 15-minute schedule via GitHub Actions. It isn't enabled because the local `gh` token lacks the `workflow` scope, which needs Tharun's browser login. |
| 13 | AI deployed with Vercel's default function region (`iad1`, US East) without checking where the database lives. Supabase is in `ap-southeast-2` (Sydney), so each query crossed the Pacific and a login plus page render took more than 30 s cold. | The production e2e run timed out on the first login redirect; a manual check showed the page did load, just slowly. `vercel inspect` showed `[iad1]` and the pooler host showed `ap-southeast-2`. | Pinned functions to `syd1` in `vercel.json` (`"regions": ["syd1"]`), next to the DB, and re-ran the production smoke test. |
| 14 | AI's first APPROACH.md draft listed two edge cases (a student replying after the owner left; resolving while waiting) as "validated" when no test covered them. | Cross-checked every row of the edge-case table against the test files before publishing. | Added two unit tests (reply with no owner → NEW and managers alerted; resolve-while-waiting counts exactly 10 h of pause), then relabelled the rows. 65 → 67 tests. |

## Validation practices used throughout (not mistakes)

- **Mutation check on the tests:** after the first green run (65/65), `canView` was deliberately broken so students could see every ticket. The suite went red on the matching test, then the file was restored. This confirmed the tests actually assert behaviour.
- **Secret hygiene:** only `DATABASE_URL` was copied from the other project, and values were never printed (only key names and lengths). `git grep` for connection strings and secrets ran before the first push, and Vercel env vars were piped from `.env.local`.
- **Shared database safety:** after setup, `information_schema` confirmed `public` still holds only its original tables (`Users`, `Tasks`, and others' `messages`, `users`); everything new is in `support_desk`.
- **Same smoke test locally and in production:** `scripts/e2e-smoke.ts` (15 checks, three roles) passed against `next start` locally and against the live Vercel URL.
